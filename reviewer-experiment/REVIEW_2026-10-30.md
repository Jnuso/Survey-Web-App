# Independent code review — October 30, 2026

At the student's request, direct review agents inspected the instructor interface, student flow, database security, results, and deployment. These were direct Codex agents, not the custom Gemma worker. Findings were checked against the source; an additional reviewer inspected the proposed frontend changes. No reviewer executed database or browser tests.

## Findings addressed

- A transient error during presentation polling could leave the QR page stuck on the error after the connection recovered. A successful poll now clears the error, and a single in-flight poll prevents slow requests from starving updates.
- Changing a multiple-choice question's type could discard entered choices without warning. The editor now asks for confirmation before replacing nonempty choices. Removing a nonempty choice also requires confirmation.
- Navigating between student survey routes could retain answers or a success screen from another survey. The student page is now recreated for each slug and ignores stale survey loads.
- Disabled or unavailable browser storage could leave submission stuck with no feedback. The student page now reports the error and re-enables the button.
- Successful results refreshes now clear a prior error message.

Verification: the production build and two existing CSV unit tests passed. In a local browser, an answer was selected, an invalid survey link was opened, and returning to the original survey showed both choices unselected. This check does not test navigating between two active surveys, storage failures, transient network recovery, or the editor confirmation dialogs. The reviewer rechecked the single-in-flight polling fix statically.

## Open findings and limits

- Results currently use multiple offset-paginated requests. During concurrent submissions, records committed between pages can shift offsets and cause a response to be missed or counted twice. A consistent database snapshot or another server-side design is needed; refreshing after submissions stop reduces exposure but is not a correctness guarantee.
- Historical date filtering and survey metadata in CSV remain incomplete, as already tracked in TODO.md.
- No anonymous access bypass was confirmed by the static security review; that does not prove the system is secure.
- Gemma itself has not reviewed this application. The existing worker's Docker engine was unavailable; see `GEMMA_REVIEW_PLAN.md` for the six planned review lanes and required evidence.
